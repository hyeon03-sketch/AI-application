# 연구 보고서: 스포츠 3D 데이터에 재활 데이터를 합치면 단일 카메라 3D 모션캡처가 재활 동작에서 Kinect를 넘는다

2026-10-31 · Sonny (AI application 팀) · 상태: 탐색(exploratory), 시드 3개 × 참가자 3-fold · English: [`RESEARCH_REPORT_EN.md`](RESEARCH_REPORT_EN.md)

---

## 결론 (첫 페이지)

> **스포츠 데이터(ASPset-510)만으로 학습한 2D→3D 모델은 재활 동작에 쓸 수 없었다. 재활 데이터(KERAAL)를 사후 카메라 보정한 뒤 학습에 합치자, 학습에 쓰지 않은 새 참가자에서 일반 카메라 1대가 Kinect 깊이 센서보다 정확한 관절 각도를 냈다.** 이 결과는 학습과 시험이 같은 방·같은 카메라일 때의 값이다(5.5절).

| | ASPset만 학습 | **ASPset + KERAAL 학습** | Kinect 센서 |
|---|---|---|---|
| KERAAL 관절 위치 오차 (MPJPE) | 222.9 ± 3.0 mm | **69.5 ± 0.8 mm** | – |
| KERAAL 관절 각도 상관 (r0) | 0.59 | **0.76** | 0.67 |
| KERAAL 관절 각도 오차 (RMSE) | 20.3° | **13.9°** | 18.7° |
| 몸통 회전 운동(RTK) 각도 상관 | 0.23 (실패) | **0.72** | 0.63 |
| ASPset test MPJPE (원래 분야) | 83.4 mm | **81.1 mm** (떨어지지 않음) | – |

값은 시드 3개 평균 ± 표준편차이고, KERAAL 값은 학습에 쓰지 않은 참가자로만 쟀다.

**핵심 발견 5가지**
1. **문제는 데이터 양이 아니라 자세 종류였다.** ASPset 학습 피험자를 3명에서 13명으로 늘려도 KERAAL 오차는 그대로였다. KERAAL 자세의 89%는 앉은 자세인데 ASPset은 13%뿐이다.
2. **보정이 없는 KERAAL을 사후 보정할 수 있었다.** Kinect를 다리로 써서 Vicon을 카메라 좌표로 옮겼다. 홀드아웃 녹화에서 3D 잔차 25mm, 투영 오차 6.2px.
3. **합쳐 학습하면 위치 오차가 약 1/3로 준다.** 222.9 → 69.5mm. 시드 × 참가자 9번 모두에서 좋아졌다.
4. **각도로 봐도 Kinect를 넘는다.** 이 각도 지표는 보정과 무관하다. 참가자 3명 모두에서 r0가 높고 RMSE가 낮다. 다만 모델은 같은 방·같은 카메라로 학습했다(5.5절).
5. **RTK 실패는 단일 카메라의 한계가 아니라 데이터 부족이었다.** 합친 뒤 r0가 0.23에서 0.72가 되어 Kinect(0.63)를 넘었다.

**주의:** 테스트 참가자는 3명(건강인, 연기한 오류)이고, 학습과 같은 방·같은 카메라에서 찍은 데이터다. 실제 환자나 다른 장소에서도 되는지는 아직 확인하지 않았다(7절).

## 3. 카메라 보정 방법

### 3.1 ASPset: 제작자가 쓴 방법 (Nibali et al. 2021, §4)

1. **촬영:** Canon EOS C200 3대, 24mm 렌즈, 4K 50fps, 무대 둘레에 약 30° 간격. 조명을 끄는 순간에 맞춰 수동으로 동기화했다.
2. **초기 보정:**
   - **비대칭 원형 패턴 보드**를 무대에서 비틀고 기울이며 움직였다.
   - **OpenCV**로 원을 검출해서 카메라별 K를 구하고, 스테레오 보정으로 E를 구했다. 이어서 경사하강법으로 세 카메라의 재투영 오차를 동시에 줄였다.
   - **렌즈 왜곡은 0으로 가정**했다.
   - 원의 행·열이 직선에서 벗어난 검출(MSE > 0.05)은 버렸고, 서로 50px 이상 다른 프레임만 남겼다(약 100장).
3. **번들 조정:**
   - 2D 관절 검출(사람 주석으로 미세조정한 Stacked Hourglass)과 카메라 파라미터를 함께 최적화했다.
   - 관절 전체에 공통인 일정한 어긋남은 허용하는 점수 U < 10px인 5,000프레임을 썼다.
4. **좌표:** 세계 좌표 = 첫 번째(left) 카메라. mm, x 오른쪽 · y 아래 · z 앞. 피험자마다 보정이 따로 있다.
5. **한계:** 정답 정확도(mm)는 보고되지 않았다.

### 3.2 KERAAL: 우리가 만든 사후 보정 (`keraal_calib.py`)

보정 보드가 없어서 **Kinect를 다리로** 썼다. 구조는 ASPset과 같다. 초기값을 구한 뒤 대응점으로 다듬는다.

```
Vicon 타깃 ──② 고정 오프셋──▶ Vicon 관절점 ──③ R, t──▶ 카메라 좌표 ──① K──▶ 픽셀
                                              ▲
                                   Kinect 관절 (카메라 좌표)
```

**① 카메라 내부값 K**
- 근거:
  - KERAAL 영상 960×540은 Kinect v2 컬러(1920×1080)의 정확히 절반이다.
  - Kinect 파일 줄 수와 영상 프레임 수가 1:1이다.
  - Kinect 관절은 이미 카메라 좌표(m)로 저장돼 있다.
- 방법:
  - 핀홀 모델을 썼다. Kinect 관절 ↔ YOLO 2D(신뢰도 > 0.5)의 12개 관절 대응으로 fx, fy, cx, cy와 컬러–깊이 센서 오프셋 t0를 함께 추정했다.
  - soft-L1 견고 최소제곱을 썼다.
  - Kinect 축(x 왼쪽, y 위)은 OpenCV 축(x 오른쪽, y 아래)으로 뒤집었다.
- 결과: **fx 502.3, fy 521.4, cx 476.0, cy 256.5, t0 = (4.8, −10.2, −19.6) cm**. 왜곡은 0으로 가정했다(ASPset과 같다).

**② Vicon 타깃 → 관절점**
- Vicon 17개는 관절 중심이 아니라 몸 마디에 붙인 강체 타깃이다. 그대로 Kinect와 맞추면 잔차가 약 12cm였다.
- 그래서 관절점 = 타깃 위치 + 타깃 회전 × **고정 오프셋**으로 두었다. 오프셋은 타깃의 로컬 좌표계 안의 상수다.

**③ Vicon → 카메라 강체 변환**
- Kinect 관절 ≈ R·(관절점) + t. 스케일은 mm로 고정했다.
- R, t(Kabsch)와 오프셋(중앙값 닫힌 해)을 **번갈아 최소제곱**으로 30번 풀었다. 중간에 한 번, Kinect 추적이 실패한 프레임(잔차가 중앙값의 3배 초과)을 버렸다.
- Vicon 60fps를 30fps로 줄였고, 녹화마다 ±15프레임 범위에서 시간 지연을 찾았다.
- **세션 = 참가자 × 운동.** 참가자당 하나로 풀면 P2만 111mm로 실패했다. 운동별로 나누면 25–33mm였다.
- 출력: 녹화마다 **ASPset `aspset_17j` 순서, 카메라 mm**의 Vicon·Kinect 관절. head_top은 대응점이 없어서 비워 두었다.

**보정 검증 (짝수 번째 녹화로 맞추고, 홀수 번째 녹화 270개로 확인)**

| 항목 | 중앙값 |
|---|---|
| Vicon 관절점 ↔ Kinect 관절 (3D) | **25.0 mm** (P1 22, P2 29, P3 23) |
| Vicon 투영 ↔ YOLO 2D | **6.2 px** (ASPset식 U 점수로 5.9 px) |
| Kinect 투영 ↔ YOLO 2D | 6.8 px |
| 오프셋 크기 | 대부분 80–230 mm |
| 눈 확인 | 홀드아웃 프레임에서 Vicon 점이 몸의 관절 위에 놓임 |

## 4. 실험 설계

| 항목 | 내용 |
|---|---|
| 입력 | YOLO11x-pose 2D(COCO 17점) + 신뢰도, 골반 중심 + 몸 크기 정규화 |
| 모델 | 시간 합성곱망(VideoPose3D 방식), 수용 영역 81프레임, 출력은 골반 기준 3D 17관절 |
| 분할 | **KERAAL 참가자 1명 빼기 3-fold.** 학습 참가자 녹화의 1/5은 KERAAL 검증용으로 뺐다. 테스트 참가자는 마지막에만 썼다 |
| 모델 선택 | (ASPset val + KERAAL val MPJPE) / 2가 가장 작은 epoch |
| 손실 | 관절별 마스크 MPJPE. 정답이 없는 관절은 손실에서 빠진다 |
| 조건 | ① ASPset만 ② ASPset + KERAAL (Vicon 정답) ③ ASPset + KERAAL (Kinect 정답) ④ KERAAL만 (Vicon 정답, 업데이트 수를 맞춰 457 epoch) |
| 학습 | AdamW lr 1e-3, 120 epoch, 좌우 반전 증강 + 테스트 시 반전 평균, **시드 0, 1, 2** |
| 지표 | **위치:** Vicon 관절점 대비 MPJPE, PA-MPJPE (head_top 제외 16관절). **각도:** Vicon **쿼터니언** 상대각과의 상관 r0와 RMSE. 각도 지표는 보정과 무관하다. **ASPset test:** 원래 분야 유지 확인 |
| 비교 | 참가자 3명 단위의 방향과 크기(시드 평균). p값은 내지 않는다 |

**Kinect 비교의 범위.** 각도 계산식과 기준은 같다: 같은 관절각 함수, 같은 Vicon 기준, 같은 시간 동기 탐색. 다만 다음은 같지 않다.
- 우리 모델은 시험 참가자와 **같은 방·같은 카메라**의 다른 사람 데이터로 학습했다. Kinect는 이 환경에 맞춰 학습되지 않았다. 그래서 이 결과는 "이 환경에 맞춰 학습하면 Kinect를 넘는다"는 뜻이고, 처음 보는 환경에서도 넘는다는 뜻은 아니다.
- Kinect 추적이 실패한 프레임은 Kinect 값에서만 빠진다.
- 어깨 각도의 몸통 축은 Kinect에서 SpineShoulder–SpineBase이고, 우리 모델에서 neck–pelvis다.

시드 × 참가자 9번 모두에서 ②, ③, ④의 위치 오차가 ①보다 작았다.

## 6. 해석: 왜 성공했나

1. **빠진 자세를 채웠다.** 가장 크게 좋아진 곳이 하체다. 발목 431 → 58mm, 무릎 376 → 55mm. ASPset만 쓴 모델은 앉은 사람의 다리를 서 있는 자세처럼 예측했다. 자세 범위 측정(앉은 자세 13% vs 89%)과 맞는다.
2. **RTK 실패는 데이터 문제였다.** r0가 0.23에서 0.72로 올랐다. 이전의 "깊이 방향 회전 = 단일 카메라 한계"라는 해석은 틀렸다.
3. **정답 형식을 ASPset과 똑같이 맞췄다.** 3.2의 보정으로 KERAAL 정답이 같은 좌표계(OpenCV 축, mm, 골반 기준, 17관절 순서)가 됐다. 그래서 모델과 손실을 바꾸지 않고 섞을 수 있었다.
4. **보정 오차가 모델 오차보다 작다.** 보정 25mm, 모델 69mm라서 정답 노이즈가 학습을 망치지 않았다.
5. **두 데이터가 서로를 지켜 준다.**
   - KERAAL에서는 ②와 ④의 차이가 작다(r0 +0.018, RMSE +0.3°).
   - 하지만 ④는 ASPset에서 315mm로 무너졌고, ②는 ASPset에서도 83.4 → 81.1mm로 오히려 좋아졌다.
   - 즉 **하나의 모델로 두 분야를 모두 다루려면 합쳐야 한다.** 논문 §6.2(MPI-INF-3DHP + ASPset)와 같은 현상이다.
6. **정답의 질이 중요하다.** Vicon 정답(②)이 Kinect 정답(③)보다 보정과 무관한 각도 r0에서도 참가자 3명 모두 높았다(+0.053). 그래서 Vicon을 카메라로 옮기는 3.2의 ②③ 단계는 할 가치가 있었다.
7. **결과가 안정적이다.** 시드 간 표준편차는 MPJPE 0.8mm, r0 0.005다. 시드 × 참가자 9번 모두에서 개선됐다.

## 7. 한계, 실패, 그리고 이유

1. **처음 보정에서 P2가 실패했다 (111mm).**
   - P2는 운동마다 카메라나 Vicon 좌표계가 바뀐 것으로 보인다. 운동별 보정으로 해결했다.
   - 실제로 카메라를 옮겼는지는 확인하지 않았다. P2는 Vicon 결측도 많다(42개 녹화가 20% 이상).
2. **ASPset만 쓴 모델의 위치 오차(223mm)에는 관절 정의 차이도 섞여 있다.**
   - KERAAL 정답은 오프셋을 Kinect 관절에 맞췄기 때문에 Kinect 정의를 따른다. ASPset은 해부학적 주석 정의를 따른다.
   - 그래서 위치 개선의 일부는 "정의를 배운 효과"다. 하지만 정의와 무관한 각도 지표에서도 크게 개선됐으므로 결론은 유지된다.
3. **손목 오차가 아직 크다 (약 150mm).** 손목 정답이 Kinect 손목(추적 불안정)에 맞춘 전완 타깃 오프셋이기 때문이다. 기능적 관절 중심(SCoRE)이나 손 타깃을 쓰면 개선될 수 있다.
4. **KERAAL만 쓴 모델은 일반화하지 못한다.** 2명, 실내, 운동 3종이라 자세 범위가 너무 좁다.
5. **표본이 작다.** 테스트 참가자는 3명이고, 통계 검정을 하기에는 부족하다.
6. **같은 방, 같은 카메라.** 새 사람에 대한 일반화는 보였지만 새 장소나 새 카메라는 확인하지 않았다. Kinect와의 비교도 이 조건에서만 유효하다(5.5절).
7. **연기한 오류만 봤다.** 실제 환자(1A)의 움직임은 다를 수 있다.
8. **ASPset 정답 자체의 정확도는 보고되지 않았다.** 논문에 mm 단위 검증이 없다.
