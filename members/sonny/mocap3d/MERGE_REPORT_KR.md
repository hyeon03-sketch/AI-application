# 실험 보고서: ASPset-510 + KERAAL G3 합쳐서 학습하기

2026-10-30 · Sonny · 상태: **탐색(exploratory)**, 시드 1개 · English: [`MERGE_REPORT_EN.md`](MERGE_REPORT_EN.md)

## 0. 요약

**실험은 성공했다.** ASPset만으로 학습한 모델은 재활 영상(KERAAL)에서 관절 위치 오차가 220mm였다. ASPset에 KERAAL 참가자 2명을 섞어 학습했더니, 학습에 쓰지 않은 세 번째 참가자에서 **69mm**로 줄었다. 위치 오차와 관계없는 각도 지표에서도 좋아져서 **Kinect보다 9개 단위 모두에서 나았다**. ASPset 성능은 떨어지지 않고 오히려 조금 좋아졌다.

| 학습 데이터 | KERAAL 위치 MPJPE (mm) | KERAAL 각도 r0 / RMSE(°) | RTK r0 | ASPset test MPJPE / PA (mm) |
|---|---|---|---|---|
| ASPset만 (기존) | 220.0 | 0.59 / 20.0 | 0.24 | 84.8 / 49.8 |
| **ASPset + KERAAL (Vicon 정답)** | **69.0** | **0.77 / 13.9** | **0.73** | **79.8 / 48.1** |
| ASPset + KERAAL (Kinect 정답) | 77.5 | 0.71 / 16.0 | 0.63 | 81.7 / 48.6 |
| KERAAL만 (Vicon 정답) | 68.9 | 0.75 / 13.6 | 0.74 | 308.2 / 193.1 |
| *참고: Kinect 센서* | – | *0.67 / 18.7* | *0.63* | – |

- 값은 참가자 1명씩 빼는 3-fold의 평균이다.
- KERAAL 지표는 학습에 쓰지 않은 참가자로만 쟀다.
- 이 실험을 가능하게 한 전제는 **KERAAL 카메라 보정**이다. 2절에 방법을 자세히 적었다.

## 1. 왜 이 실험을 했나

- ASPset만으로 학습하면 KERAAL 각도 오차가 20° 근처에서 멈췄다. 학습 피험자를 3명에서 13명으로 늘려도 그대로였다(학습 곡선, 10/30).
- 자세 커버리지를 재 보니 원인이 보였다. KERAAL 자세의 89%는 앉은 자세인데 ASPset은 13%뿐이다. KERAAL 프레임의 62%는 ASPset에 비슷한 자세가 없다.
- 그래서 **"ASPset을 더 쓰는 것"이 아니라 "재활 자세를 학습에 넣는 것"**이 답일 것이라고 보고, 두 데이터셋을 합쳐 보았다.
- KERAAL을 학습에 쓰려면 ASPset과 같은 형식의 3D 정답이 필요하다. 형식은 **카메라 좌표, mm, 골반 기준, 같은 17관절 정의**다. KERAAL에는 카메라 보정이 없으므로 보정을 먼저 만들었다.

## 2. 카메라 보정: 어떤 방식을 썼나

### 2.1 ASPset 제작자의 방식 (논문 확인: Nibali et al. 2021, §4)

| 단계 | 방법 |
|---|---|
| 촬영 | Canon EOS C200 3대, 24mm 렌즈, 4K 50fps, 무대 둘레에 약 30° 간격 |
| 동기화 | 소프트웨어 방식. 세 카메라 앞에서 조명을 끄는 순간에 맞춰 수동 정렬 |
| 초기 보정 | **비대칭 원형 패턴 보드**를 무대에서 비틀고 기울이며 이동시켰다. **OpenCV**로 원 검출 → 카메라별 K → 스테레오 보정으로 E → 경사하강법으로 세 카메라 재투영 오차를 동시에 최소화. **렌즈 왜곡은 0으로 가정**. 행·열 직선성(MSE 0.05)으로 나쁜 검출을 버리고, 50px 이상 다른 프레임만 남겼다(시퀀스당 약 100장) |
| 다듬기 | **번들 조정**: 2D 관절 검출(사람 주석으로 미세조정한 Stacked Hourglass)과 카메라 파라미터를 함께 최적화. 관절 전체에 공통으로 생기는 일정한 어긋남은 허용하는 U 점수 < 10px인 5,000프레임 사용 |
| 좌표 | 세계 좌표 = 첫 번째(left) 카메라, mm, x 오른쪽 · y 아래 · z 앞. 피험자(세션)마다 보정이 따로 있다 |
| 한계 | 정답 정확도(mm)는 보고되지 않았다 |

### 2.2 우리가 KERAAL에 쓴 방식 (`keraal_calib.py`)

보정 보드가 없으므로, **Kinect를 다리로 쓰는 사후(post-hoc) 보정**을 했다. 구조는 ASPset과 같다. 초기값을 구한 뒤 2D 관절로 다듬는다.

```
Vicon 타깃(위치+쿼터니언) ──② 오프셋──▶ Vicon 관절점 ──③ R,t──▶ 카메라 좌표 ──① K──▶ 픽셀
                                                  ▲
                                         Kinect 관절 (카메라 좌표)
```

**① 카메라 내부값 K: Kinect 관절 ↔ 영상 2D 검출**
- 근거: KERAAL 영상(960×540)은 Kinect v2 컬러 카메라(1920×1080)의 절반 해상도이고, Kinect 파일 줄 수와 영상 프레임 수가 1:1이다. Kinect 관절은 이미 카메라 기준 좌표(m)다.
- 방법: 핀홀 모델 `u = fx·X/Z + cx`. Kinect 관절과 YOLO 2D(신뢰도 > 0.5)의 12개 관절 대응으로 fx, fy, cx, cy와 **컬러–깊이 센서 오프셋 t0**를 함께 추정했다. 견고 최소제곱(soft-L1)을 썼고, 보정용 녹화 270개에서 5프레임마다 뽑았다.
- 축 변환: Kinect(x 왼쪽, y 위) → OpenCV(x 오른쪽, y 아래)로 x, y 부호를 뒤집었다.
- 결과: **fx 502.3, fy 521.4, cx 476.0, cy 256.5, t0 = (4.8, −10.2, −19.6) cm**. 렌즈 왜곡은 ASPset처럼 0으로 가정했다.

**② Vicon 타깃 → 관절점: 타깃별 고정 오프셋**
- 문제: Vicon 17개는 관절 중심이 아니라 몸 마디에 붙인 **강체 타깃**이다. 타깃을 그대로 Kinect 관절과 맞추면 잔차가 약 12cm였다.
- 모델: 관절점 = 타깃 위치 + 타깃 회전(쿼터니언) × **고정 오프셋 o_j**. 각 타깃의 로컬 좌표계에서 관절이 있는 위치를 하나의 상수로 둔 것이다.
- 쿼터니언 방향 규약(그대로 쓸지, 켤레로 쓸지)은 잔차가 작은 쪽을 고른다. 결과는 모든 세션에서 "그대로"였다.

**③ Vicon → 카메라: 세션별 강체 변환 R, t**
- 모델: Kinect 관절(카메라 mm) ≈ R·(관절점) + t. 스케일은 고정(mm)이다.
- 풀이: R, t(Kabsch)와 오프셋 o_j(닫힌 해, 중앙값)를 **번갈아 최소제곱**으로 30번 반복했다. 중간에 한 번, 잔차가 중앙값의 3배를 넘는 Kinect 추적 실패 프레임을 버렸다.
- 시간 맞추기: Vicon(60fps)을 30fps로 줄이고, 녹화마다 ±15프레임 범위에서 지연을 찾았다.
- **세션 = 참가자 × 운동.** 처음에는 참가자당 하나로 풀었다. P2만 잔차 111mm로 실패했는데, 운동별로 나누면 25–33mm였다(4.1절). 운동마다 카메라나 Vicon 좌표계가 바뀐 것으로 보인다.
- 최종 출력: 녹화마다 Vicon과 Kinect 관절을 **ASPset `aspset_17j` 순서, 카메라 mm**로 저장했다(`E:\KERAAL_mocap3d\calib\gt3d\`). head_top은 대응하는 점이 없어서 NaN이다.

**검증: 짝수 번째 녹화로 맞추고, 홀수 번째 녹화 270개로 확인**

| 항목 | 결과 (중앙값) |
|---|---|
| Vicon 관절점 ↔ Kinect 관절 3D 거리 | **25.0 mm** (처음 12cm에서 줄어듦). 참가자별 P1 22, P2 29, P3 23 |
| Vicon 투영 ↔ YOLO 2D | **6.2 px** (일정한 어긋남을 허용하는 ASPset U 방식으로는 5.9 px) |
| Kinect 투영 ↔ YOLO 2D | 6.8 px |
| 오프셋 크기 | 대부분 80–230mm (타깃이 관절에서 떨어진 거리로 그럴듯함) |
| 눈으로 확인 | 홀드아웃 프레임 투영에서 Vicon 점이 몸의 관절 위에 놓임 (`E:\KERAAL_mocap3d\calib\overlay_check.png`, 공개 금지) |

> **주의:** 오프셋은 "Kinect 관절과 가장 잘 맞는 위치"로 정해진다. 그래서 KERAAL의 3D 정답은 **Kinect의 관절 정의를 따른다**. 순수한 해부학적 관절 중심이 아니다. 평가에 미치는 영향은 4.3절에 적었다.

## 3. 합치기 실험 설계

| 항목 | 내용 |
|---|---|
| 입력 | YOLO11x-pose 2D (COCO 17점) + 신뢰도, 골반 중심 + 몸 크기 정규화 (기존과 같음) |
| 모델 | 시간 합성곱망(VideoPose3D 방식), 수용 영역 81프레임, 출력 `aspset_17j` 골반 기준 3D |
| 분할 | **참가자 1명 빼기 3-fold.** KERAAL 학습 참가자 2명의 녹화 중 5개에 1개는 KERAAL 검증용으로 뺐다. 테스트 참가자는 끝날 때까지 쓰지 않았다 |
| 모델 선택 | (ASPset val MPJPE + KERAAL val MPJPE) / 2가 가장 작은 epoch |
| 손실 | 관절별 마스크 MPJPE. KERAAL의 head_top이나 Vicon 결측은 손실에서 빠진다 |
| 조건 | ① ASPset만 (기존 det/root seed 0 모델 재평가) ② ASPset + KERAAL (Vicon 정답) ③ ASPset + KERAAL (Kinect 정답, 보정 ②③ 없이 가능) ④ KERAAL만 (Vicon 정답, 같은 업데이트 수가 되도록 457 epoch) |
| 학습 | AdamW lr 1e-3, 120 epoch, 좌우 반전 증강 + 테스트 시 반전 평균, seed 0 |
| 데이터 양 | KERAAL 학습 약 288개 녹화(약 6.4만 프레임). ASPset 학습 1,170개 시점(24.3만 프레임) |
| 지표 | **위치**: Vicon 관절점 대비 MPJPE, PA-MPJPE (head_top 제외 16관절) · **각도**: 기존 `keraal_eval.py`. Vicon **쿼터니언** 상대각과의 상관 r0와 RMSE이며, **보정과 무관한 독립 지표**다 · ASPset test |
| 검정 | 테스트 참가자 × 운동 9개 단위의 Wilcoxon 부호순위 검정 |

## 5. 성공한 이유

1. **빠진 자세를 채웠다.** ASPset에는 앉은 자세가 13%뿐이었다. KERAAL을 넣자 가장 크게 좋아진 곳이 하체였다. 발목은 430 → 56mm, 무릎은 376 → 54mm로 줄었다. ASPset만으로 학습한 모델은 앉은 사람의 다리를 서 있는 자세처럼 펴서 예측했던 것으로 보인다.
2. **RTK 실패가 풀렸다.** 몸통 회전 운동의 r0가 0.24에서 0.73이 되어 Kinect(0.63)를 넘었다. 단일 카메라의 원리적 한계가 아니라 **학습 데이터에 그 동작이 없어서** 생긴 실패였다는 뜻이다. 앞서 "깊이 방향 회전 = 단일 카메라 한계"로 해석한 부분은 고쳐야 한다.
3. **정답 형식을 ASPset과 똑같이 맞췄다.** 2절의 보정으로 KERAAL 정답을 같은 카메라 좌표계(OpenCV 축, mm, 골반 기준, 17관절 순서)로 옮겼다. 덕분에 모델 구조나 손실을 바꾸지 않고 섞을 수 있었다.
4. **보정이 충분히 정확했다.** 홀드아웃 3D 잔차는 25mm, 투영은 6px이다. 우리 모델의 오차(69mm)보다 충분히 작아서, 정답 노이즈가 학습을 망치지 않았다.
5. **두 데이터가 서로를 보완했다.** KERAAL만으로 학습하면 KERAAL 성능은 비슷하지만 ASPset에서 무너졌다(308mm). 합쳐서 학습하면 두 분야 모두 좋았고, ASPset도 85 → 80mm로 좋아졌다. 다른 카메라와 다른 사람을 본 것이 일반화에 도움이 된 것으로 보인다. 논문(§6.2)에서 MPI-INF-3DHP와 ASPset을 합쳤을 때 실내 결과까지 좋아진 것과 같은 현상이다.
6. **Vicon 정답이 Kinect 정답보다 낫다.** Kinect를 정답으로 쓴 모델도 좋아졌지만 Vicon 쪽이 모든 지표에서 앞섰다. 보정과 무관한 각도 r0도 0.77 vs 0.71이다. 더 깨끗한 정답이 실제로 차이를 만든다. 그래서 2절의 ②③ 단계(Vicon을 카메라로 옮기기)는 할 가치가 있었다.
7. **참가자 단위로 일반화했다.** 학습에 쓰지 않은 참가자에서, 9개 단위 모두에서 Kinect보다 나았다. 같은 사람을 외운 것이 아니다.

## 6. 실패했거나 남은 문제, 그리고 이유

1. **처음 보정에서 P2가 실패했다 (111mm).**
   - 이유: P2는 운동마다 카메라나 Vicon 좌표계가 달라졌던 것으로 보인다. 운동별로 따로 풀면 25–33mm가 된다.
   - 아직 확인하지 않은 점: 실제로 카메라를 옮겼는지(영상 배경 비교), P2의 Vicon 결측이 유독 많은 것(42개 녹화가 20% 이상 결측)과 관련이 있는지.
2. **ASPset만 쓴 모델의 KERAAL 위치 오차는 220mm로 매우 컸다.**
   - 이유 1: 앉은 다리 자세가 학습에 없었다(5-1).
   - 이유 2: 관절 정의가 다르다. KERAAL 정답은 Kinect 정의를 따르고, ASPset은 사람이 주석한 해부학적 정의를 따른다. 그래서 220mm 중 일부는 자세 오류가 아니라 **정의 차이**다. 정의를 같이 배우는 합친 모델은 그만큼 유리하다. 이 효과를 분리하려면 각도 지표(4.3)를 함께 봐야 하는데, 각도에서도 큰 개선이 있었으므로 결론은 같다.
3. **KERAAL만으로 학습한 모델은 ASPset에서 무너졌다 (308mm).**
   - 이유: 참가자 2명, 실내, 앉은 팔 운동 3종뿐이라 자세 종류가 너무 좁다. 그래서 KERAAL만으로는 일반 모델이 될 수 없다.
4. **손목 오차가 아직 크다 (약 147mm).**
   - 이유: 손목 정답은 Vicon 전완(forearm) 타깃에 오프셋을 더한 것이다. 오프셋이 Kinect 손목에 맞춰져 있는데, Kinect 손목은 추적이 불안정하다.
   - 개선 방법: 손(hand) 타깃을 함께 쓰거나, 두 타깃의 기능적 관절 중심(SCoRE)을 쓴다.
5. **정답이 Kinect의 관절 정의를 따른다.**
   - 이유: 오프셋을 Kinect 관절에 맞춰 정했다.
   - 영향: 위치 지표가 "Kinect처럼 예측하기"에 유리하다. 반면 각도 지표는 Vicon 쿼터니언에서 나오므로 영향을 받지 않는다.
   - 개선 방법: Kinect가 필요 없는 기능적 관절 중심으로 바꾸고 다시 확인한다.
6. **통계적 힘이 약하다.**
   - 참가자 3명, 시드 1개다. 9개 단위 검정은 p < 0.01이지만 단위가 독립적이지 않다(같은 사람의 운동 3개).
   - 개선 방법: 시드 3개(약 3시간), 그리고 다른 그룹(1A 환자, 2A 건강인)의 영상으로 외부 검증. 이 그룹들은 Vicon이 없고 Kinect만 있어서 각도로만 평가할 수 있다.
7. **KERAAL 학습 데이터와 테스트 데이터가 같은 방, 같은 카메라다.**
   - 이유: G3는 한 장소에서 녹화됐다.
   - 영향: "새 사람"에는 일반화했지만 "새 장소나 새 카메라"에는 확인하지 못했다. OpenCap 같은 외부 데이터로 확인해야 한다.
8. **연기된 오류(G3)만 봤다.**
   - 실제 환자(1A)의 움직임에서도 이렇게 될지는 모른다.

## 7. 연구에 주는 의미

- **논문 주장 후보:** "스포츠 3D 데이터만으로는 재활 자세가 부족하다(커버리지 13% vs 89%, 데이터를 늘려도 그대로). 보정이 없는 재활 데이터셋을 Kinect를 다리로 사후 보정하고 섞으면, 새 참가자에서 단일 카메라 영상이 Kinect보다 정확한 관절 각도를 낸다(9/9 단위)."
- **바뀐 해석:** RTK 실패는 단일 카메라의 한계가 아니라 데이터 부족이었다. `RESULTS.md`의 결과 5를 고쳐야 한다.
- **다음 순서:**
  1. 시드 3개로 다시 실행한다.
  2. 손목 정답을 개선한다(기능적 관절 중심).
  3. 1A/2A 영상에 적용해서 Kinect와 각도를 비교한다(E2 확인 후).
  4. 오류 판별(RQ4)을 합친 모델로 다시 돌린다.
  5. 외부 검증(OpenCap)을 한다.
